# YIFUN Workplace · 完整页面版

本地统一入口：**http://127.0.0.1:8975**。

双击 **启动完整页面版.command**。第一次使用先建立管理员账号，再建立岗位账号和项目成员。启动器会启动独立的本机后台服务：关闭启动窗口不会停止服务，中心服务退出后自动恢复。重启 Mac 后需再次双击启动器。双击 **停止后台服务.command** 可停止后台服务；再次双击启动器即可恢复。此地址只在这台 Mac 上可用，关机或睡眠期间不可访问。

本版位于独立目录 workplace-complete，沿用 V2 的报价、采购、仓库验收、售后、CEO 看板及项目权限。原 workplace-v2 和线上服务未被覆盖。正式业务库保持独立，未导入线上资料；qa/ 中全部是明确标记的测试资料。

## 业务顺序

销售确认并锁定报价 → 工程编制、核对并下达工程单 → 满足订金条件或 CEO 特批 → 采购下单 → 发货 → 仓库收货验收 → 共用库存 → 客户交付／安装 → 售后。

工程可以标记工厂执行去向，工厂生产执行功能仍在后续范围。项目采购必须关联已下达工程单；工程规格、图纸版本及执行去向保留在该工程版本中。管理员监管，CEO 仍是唯一特殊放行审批人。

## 页面与使用

完整列表见「页面清单.md」。员工从我的待办进入任务、安装与现场问题；管理员可监管项目、分配人员并导入主档；CEO 总看板汇总项目和异常。

工程下单：从已确认销售订单建立工程单，核对每行规格、图纸及去向；可上传附件，草稿完成后下达。已下达版本不可改写。详情可追踪关联采购的数量、收货和入库。

库存作业：同一库存账本按仓库和库位查看，调拨成对记录。采购验收形成的库存先记在「待分配库位」，仓库按实际存放位置办理调拨；此处不另建一份售后库存。出库时选择实际库位。待检及不良品库位不计入可用数量。

盘点管理：保存盘点草稿后核对差异并入账；期间发生库存变动时须重新盘点。不会重复入账或扣减已占用数量。

现场反馈：选择项目、填写问题和位置、负责人、期限及影响情况，提交后可追加照片／文件。处理人填写结果，现场提交人确认关闭；阻碍安装的问题未关闭时不能确认安装验收。

退换返修：关联实际交付记录；销售确认责任和差额处理说明，仓库将退回产品收进待检库位，再由售后或采购记录实物处置及补发凭证。客户 Credit 仍由后续开放的财务功能处理，不自动改写报价或生成退款。

档案导入：支持 UTF-8 CSV 的客户、项目和产品，页面可下载模板。先导入客户，再按客户编号关联项目。每批最多 500 行，先显示重复、冲突及负责人问题，再确认导入；保留来源和旧编号。已有档案不覆盖，库存不叠加。复杂历史报价、合同及期初库存的迁入仍须单独核对。

## 财务边界

财务保持关闭。费用登记界面可以查看，但保存与附件接口均受关闭状态保护；收付款、Credit 及补价接口继续关闭。项目成本按币种分别展示已记录采购与预算，完整费用尚未接入时不显示虚构利润。完整会计总账和税务不属于本次页面范围。

## 本机数据与检查

唯一业务数据库：data/workplace.sqlite3。新页面附件也保存在该数据库中；原生中心附件位于各自本机对象存储，随现有备份工具处理。

35 项规则及回归检查通过，见 qa/ceo-final-tests.log。CEO 看板现分为经营总况与财务资金分析，支持项目和日期筛选、明细跳转、全屏及 CSV 导出，具体口径见「CEO看板说明.md」。原生三中心采购至验收入库联调见 qa/native-chain-result.json。界面检查由 Codex 浏览器完成，详情见验收记录.md。

复查业务规则：python3 -m unittest discover -s tests -p 'test_*.py' -v。

本版只绑定本机地址，未部署上线。默认启动不会加载 qa/ 测试资料。
